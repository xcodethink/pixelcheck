## Summary

**No functional change. `dist/` is byte-identical to 1.4.0** — verified by diffing
the two tarballs before publishing: same 421 files, identical `dist/` trees, and
6.7 KB smaller compressed.

The release exists because `files` includes `CHANGELOG.md`, so the **1.4.0
tarball on npm shipped roughly 3,700 CJK characters of old internal work log**.
Cleaning the repository does not clean what is already published; only a new
version does.

Headlines:

- **The published package is English-only.** `CHANGELOG.md` and `README.md` in
  the 1.4.1 tarball contain zero CJK characters. The 2,627 that remain are the
  localisation feature itself — the i18n tables and the `cn` / `tw` / `jp`
  personas — which is intended and enforced by an allowlist rather than by
  memory.
- **Registry publishing is automated.** This is the first release where
  `server.json` reached `registry.modelcontextprotocol.io` without a manual
  step. Publishing had been manual and was silently skipped for 1.2.1, 1.3.0 and
  1.4.0, leaving the registry two versions behind.
- **A drift gate exists.** Contract tests assert `server.json` agrees with
  `package.json` on version, namespace and package identifier — the exact gap
  that let the registry fall behind unnoticed.
- **Documentation is English throughout.** Nine ADRs written in Chinese are
  translated; the v1.0.0 changelog section, 224 lines of Chinese work log, is
  rewritten as English release notes.
- **`projects/` is gone,** along with a real name, two absolute local
  filesystem paths, references to a maintainer's private global configuration,
  and dead links to non-public planning documents.

## History rewrite (relevant to every SHA in this repository)

Between 1.4.0 and 1.4.1, git history was rewritten **twice** to remove paths
that should never have been public:

| Round | Paths removed | Why |
|---|---|---|
| 1 | `projects/` (20 files) | Operator-private audit scaffolding for two unrelated projects — their domains plus signup, admin-panel, paywall, purchase and extension-install flows. `.gitignore` declared the directory operator-private on 2026-05-03, but part of it had been committed on 2026-04-24, and `.gitignore` does not apply to already-tracked files. |
| 2 | one product-specific config file, `.env.development` | The config carried another project's admin URL and the names of its admin-cookie / Slack / Telegram variables; the env file carried local absolute paths. Neither held secret values. |

Consequences, recorded rather than hidden:

- **Every commit SHA changed**, twice. `v1.4.0` now points at
  `bd507adb9f97721a6941c4adfe819dda896bad8e`; the SHA recorded in
  `2026-07-26-v1.4.0.md` predates both rewrites and no longer resolves. That
  record is deliberately **not** back-filled — a release record edited quietly
  after the fact is not a record.
- **The npm provenance attestation for 1.4.0 still references the original
  commit.** It remains cryptographically valid; only the GitHub link 404s.
  1.4.1's attestation references `7e717eb`, which is current.
- Both protection layers (classic branch protection and the `main-protection`
  ruleset) were unlocked for the force-push and restored from a field-by-field
  snapshot afterwards. Verified: `enforce_admins=true`,
  `allow_force_pushes=false`, `allow_deletions=false`, ruleset `active` with
  `deletion` and `non_fast_forward`.

## Rollback plan

npm tarballs cannot be unpublished after 72h; rollback is fix-forward.

- **Code**: `git revert 7e717eb` on a branch → PR → merge. `main` is protected;
  never `reset --hard`.
- **npm (within 72h, emergencies only)**: `npm unpublish pixelcheck@1.4.1`, then
  `npm dist-tag add pixelcheck@1.4.0 latest`.
- **npm (after 72h)**: `npm deprecate pixelcheck@1.4.1 "use 1.4.2"` and ship a
  patch.
- **Re-point `latest` without unpublishing**: `npm dist-tag add pixelcheck@1.4.0 latest`.
- **Note**: rolling back to 1.4.0 re-exposes the Chinese changelog in the
  published tarball. Prefer fixing forward.

## Follow-ups

- **`NPM_TOKEN` expiry**: the granular automation token was issued 2026-06-02
  with a 90-day window (~2026-08-31). It worked for this publish. Rotate before
  expiry, or migrate to npm **Trusted Publishing** — worth doing now that the
  registry workflow has proven OIDC works end to end with no stored secret.
- **`darwin-x64` has no CI coverage** since `macos-13` left the matrix.
  `better-sqlite3` and `sharp` ship per-architecture prebuilds, so a regression
  there would surface from users rather than CI. Revisit if GitHub offers a
  working Intel macOS image.
- **Git history still contains the pre-cleanup Chinese documentation.** Removing
  a path from history is not the same as rewriting file *contents* in every
  commit. New clones get English files; `git log -p` on old commits still shows
  the original Chinese. Cleaning that would mean rewriting content across the
  whole history, which was judged not worth the cost.
- **`@ai-sdk/provider-utils`** (17 low) clears when upstream stagehand updates
  its `@ai-sdk` dependencies. Out of production scope.
