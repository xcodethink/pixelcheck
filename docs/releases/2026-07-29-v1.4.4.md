## Why this release exists

Nothing here changes for a consumer. It was cut to exercise the publish path.

npm trusted publishing had just been configured, and **npm does not validate
that configuration when it is saved** — a wrong organisation, repository or
workflow filename surfaces only as a failed publish. The only way to know it
works is to publish with it.

**The timing was the point.** The stored token was still wired in as a fallback
and had 34 days left, so this was a test with a safety net: a misconfiguration
would have fallen through to the token and stalled nothing. Waiting for the
first attempt until the token had expired would have meant discovering the
problem with no way out.

### A verification trap worth recording

**`npm view … _npmUser` collapses that object into a display string and drops
the `trustedPublisher` field.** Checking it that way reports what looks like a
token publish. The registry document has to be queried directly.

This corrects an earlier claim in this project's notes that npm exposes no
signal distinguishing OIDC from token publishing. It does — the field above,
which the npm website renders as a "GitHub Actions" publisher badge.

### Follow-on

The token fallback was removed immediately afterwards, so **the repository now
holds no publish credential of any kind**. Beyond retiring an expiring secret,
this matches where the registry is going: npm restricts 2FA-bypassing tokens
from August 2026 and direct publishing from January 2027.

The new failure mode is documented in the workflow header: **renaming
`release.yml` breaks publishing**, because the trusted publisher configuration
matches on filename.

## What actually ships

- **`npm run build` restores the executable bit on the bin entry points.** `tsc`
  emits 0644 files and the shebang is inert without that bit; npm sets it only
  at install or link time, so `npm run clean && npm run build` in a linked
  development checkout left `pixelcheck` failing with "permission denied".
  Verified that consumers installing from the registry were never affected —
  `npx pixelcheck` and the `.bin` symlink both work from a tarball installed
  into a clean directory. `scripts/chmod-bins.mjs` reads the `bin` map so a new
  entry is covered automatically, and fails the build if a declared bin was not
  produced.
- **Branch protection now requires every platform the package claims to
  support.** Nine checks instead of four: both Node versions on ubuntu-latest,
  macos-14 and macos-15-intel, plus the Playwright run, the coverage gate and
  dogfood. Windows stays excluded on purpose — its jobs run with
  `continue-on-error` because of unresolved cross-process races, so requiring
  one would be a check that cannot fail.

Neither is observable from an installed package.

## Rollback plan

npm tarballs cannot be unpublished after 72h; rollback is fix-forward.

- **Code**: `git revert b26a7ec` on a branch → PR → merge.
- **npm (within 72h, emergencies only)**: `npm unpublish pixelcheck@1.4.4`, then
  `npm dist-tag add pixelcheck@1.4.3 latest`.
- **npm (after 72h)**: `npm deprecate pixelcheck@1.4.4 "use 1.4.5"` and ship a
  patch.
- **Publishing itself cannot be rolled back to tokens without work**: the
  fallback is gone from `release.yml`. If trusted publishing ever breaks, either
  fix the npmjs.com configuration or re-add `NODE_AUTH_TOKEN` with a fresh
  token — the old one expires around 2026-08-31 regardless.

## Follow-ups

- **Delete the `NPM_TOKEN` secret**, on npmjs.com and in the repository
  settings. Nothing references it any more; it is an unused credential.
- **Consider the strictest publishing-access setting** on npmjs.com — *require
  two-factor authentication and disallow tokens*. It was not safe to select
  while the token fallback existed; now it is.
- **Windows is still not a required check** because of the cross-process test
  races behind its `continue-on-error`. Fixing those and dropping the flag is
  what closes the gap between the support claim and the gate.
- **`macos-15-intel` disappears in August 2027** — the last x86_64 image GitHub
  will offer. Both Intel checks must then come out of the matrix *and* the
  required-checks list.
- **`@ai-sdk/provider-utils`** (17 low) clears when upstream stagehand updates
  its `@ai-sdk` dependencies. Out of production scope.
