# Release v2.0.0 — Node 20 dropped, and four surfaces that did not do what they said

## Why this release is a major

`engines.node` moves from `>=20.0.0` to `>=22.0.0`. Node 20 reached
end-of-life on 2026-04-30, but the forcing function was concrete rather than
calendar-based: `better-sqlite3` stops shipping a prebuilt binary for Node
20's ABI after 12.9.0.

```
$ curl -s https://api.github.com/repos/WiseLibs/better-sqlite3/releases/tags/v12.9.0  | jq -r '[.assets[].name] | …'
12.9.0   ABI: 115, 121, 123, 125, 127, 128, 130, 131, 132, 133, 135, 136, 137, 139, 140, 141, 143, 145
12.11.1  ABI:      121, 123, 125, 127, 128, 130,      132, 133, 135, 136, 137, 139, 140, 141, 143, 145, 146, 147
```

ABI 115 is Node 20. Staying on it meant either holding an old dependency or
compiling from source on every install, which is why the pending dependency
update could not be merged as a routine patch.

## What actually ships

Four surfaces were doing something other than what they claimed. Each was
found by running the thing, not by reading it.

**The `--observe` dashboard did not work at all.** The auth token was added to
the server and never delivered to the pages. The WebSocket was closed with
4001 and two API calls returned 401 inside a `catch (e) { /* offline, ignore
*​/ }`, so the page read "Disconnected" with no explanation. `replay` printed
no address at all.

**Two observer routes answered unauthenticated.** `/api/grid` and
`/api/session/:id` were matched above the auth check and returned early — the
latter with a session's state and its last 200 events. A request with no token
returned an event reading `Type hunter2-REAL-PASSWORD into the password
field`. The exemption existed because the grid page called them without a
token, and had been recorded in the test suite as intended behaviour.

**Both reports and the dashboard executed audit data.** Free text was escaped;
the enum-typed fields were not, which holds only while the object comes
through the Zod boundary — and `writeHtmlReport`, `writeSpaReport` and
`loadAuditReport` are all exported, the last of them casting parsed JSON with
no schema. Measured in Chromium: three executions in `audit.html`, six in
`audit-explorer.html`, zero after.

**Input redaction missed frames and corrupted what it reached.** It walked
only the main frame's light DOM, so a card number inside an iframe kept its
value — while its own documentation named Stripe, which renders fields in
exactly such a frame. And the replacement was permanent: fill a password, take
a screenshot, submit, and the form submitted `********`. The site rejects the
login and the audit records a finding against the site for a fault in this
tool.

Also: seven copies of `escapeHtml` that disagreed became one; 28 internal
identifiers were removed from source that compiles into `dist`; the high
advisories were cleared, including one an override added for an earlier
advisory was holding open.

## Database migrations

None. This product has no server-side database; the local SQLite cache is
created on demand and its schema is unchanged.

## What went wrong on the way, and is worth knowing

**Three required checks would have bricked `main`.** Branch protection required
`Test (… · Node 20)` on three platforms. Those names stop existing when the
matrix changes, so the pull request sat at `state=BLOCKED` with every check
green — `gh pr checks` counts what ran, not what was required and missing. The
contexts were moved to Node 24 through the dedicated status-checks endpoint,
not a full protection PUT, which would have risked dropping `enforce_admins`
and the force-push block; every other field was compared before and after.

**Four gates would have stopped running silently.** `lint`, `license:check`,
`check:vendor-integrity` and `check:vendor-drift` are gated on
`matrix.node == 20` so they run once per push rather than once per cell.
Removing 20 leaves those conditions matching nothing, with nothing failing to
say so. They are re-anchored, and the matrix now carries a comment saying they
must move with it.

**43 internal identifiers shipped in this version.** They were found while
verifying the published tarball, in the form `(Audit 2026-06-02 E2.)` — 34 of
them in `src/`, which compiles into `dist`. Four previous rounds of the
identifier gate had enumerated prefixes; this form hangs off an attribution
phrase, and matching the phrase caught the whole family at once. Fixed after
the release: 2.0.0 carries them and cannot be changed, and unpublishing would
be worse than the identifiers.

## Rollback plan

Code:

```
npm dist-tag add pixelcheck@1.4.4 latest    # point installs back at 1.4.4
git revert --no-commit v1.4.4..v2.0.0       # if the tree must go back too
```

`npm unpublish` is not the rollback. Within 72 hours it removes the version
entirely, which breaks any lockfile already referencing it; after that it is
unavailable. Moving the `latest` tag is reversible and does not break anyone
who has already installed.

Consumers on Node 20 who cannot upgrade the runtime:

```
npm install pixelcheck@1.4.4
```

1.4.4 remains published and installable; nothing about it changes.

## Follow-ups

- The identifier gate now matches attribution phrases. Shape-matching was
  measured and rejected: `[A-Z]` plus one or two digits matches 57 distinct
  tokens here, mostly legitimate (`P0` priorities, `H1` headings, `A4` paper,
  `B64`, `X11`).
- `removeComments: true` would end the category for the published artefact,
  at the cost of 2480 lines of JSDoc in the `.d.ts` files. Not taken; it is a
  product decision about API documentation, not a cleanup.
- Windows remains `continue-on-error` in CI.
- `audit.json` still records only executed units, not planned ones; a CI
  consumer reading the artefact rather than the terminal cannot see a
  budget-truncated run.
