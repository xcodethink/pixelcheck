# Release v2.1.0 — the report says how much of the matrix ran

## Why this is a minor and not a patch

Everything in this release could be read as housekeeping except one thing:
`summary.planned` adds a field to the report contract, and
`RESULT_SCHEMA_VERSION` moves 1.3.0 → 1.4.0.

SemVer calls added functionality a minor. Shipping it as 2.0.1 would leave
anyone pinned to `~2.0.0` unable ever to receive the field — which is the only
substantive change here, so the patch number would have hidden the one thing
worth upgrading for.

## What actually ships

**`summary.planned`.** A unit skipped on budget, or dropped because its persona
was missing, never reaches `results`, so `summary.total` counts what answered
rather than what was asked for. A three-unit matrix truncated after the first
recorded `total: 1` — indistinguishable, in the artefact, from a one-unit
matrix that ran to completion, and if that unit passed, from a clean audit of
all three. The CLI could print the gap because it holds the matrix in memory; a
CI job reading `audit.json` could not see it at all.

Optional in the schema so every report written up to v2.0.0 still parses;
required in the TypeScript type so the runner cannot omit it — TypeScript
caught two script call-sites that would otherwise have. Absent means unknown,
not zero.

**The internal identifiers v2.0.0 shipped with.** Forty-three were still in the
tree, thirty-four in `src/`, which compiles into `dist`. They were found while
verifying the v2.0.0 tarball, so v2.0.0 carries them and 2.1.0 does not:

```
2.0.0 → 5 files containing an attribution phrase
2.1.0 → 0
```

The gate now matches the phrase the identifiers hang off rather than
enumerating prefixes, which four earlier rounds had done and which is why this
family survived.

**Two records rather than fixes.** The file-lock contention test keeps stderr
when a child dies — it previously reduced a crash to `expected false to be
true`. And `SECURITY.md` now says why the seventeen low advisories cannot be
cleared, with the failing module graph pasted in.

## Rollback plan

```
npm dist-tag add pixelcheck@2.0.0 latest    # point installs back at 2.0.0
git revert --no-commit v2.0.0..v2.1.0       # if the tree must go back too
```

`npm unpublish` is not the rollback: within 72 hours it removes the version
entirely and breaks any lockfile referencing it; after that it is unavailable.

Nothing in this release is breaking, so a consumer on 2.0.0 loses only
`summary.planned` by staying there. A consumer already reading that field
would need code changes to go back, which is the usual asymmetry of an
additive schema change.

## Follow-ups

- Windows remains `continue-on-error`. Measured on the last 15 CI runs on
  `main`: 14 green, 1 failed, longest run of consecutive green 14. The
  project's threshold for removing it is 20, so this closes itself with six
  more green runs and needs no action.
- The seventeen low advisories stay until the AI SDK family moves together.
  `SECURITY.md` says not to re-attempt the override on the strength of
  `npm audit`'s `fixAvailable` flag, and pastes what happens if you do.
- Calibration bands are still wide enough that a model scoring 1 and a model
  scoring 6 on the same dimension both read as agreement. The instrument to
  measure that exists (`npm run compare:critics`); running it enough times to
  draw a conclusion costs money and has not been done.
- The default critic models remain a generation behind, for the same reason.
