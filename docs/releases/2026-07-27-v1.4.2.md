## Summary

Mostly packaging: `dist/` differs from 1.4.1 almost entirely in comment text.
The one real behaviour change is `ADMIN_COOKIE`.

### The behaviour change

`src/core/secrets.ts` read an environment variable whose name embedded the
product name of this tool's first user. `.env.example` has documented the
generic `ADMIN_COOKIE` since 1.1.3, and the 1.1.3 release notes state the rename
happened — but only the example file was changed. The consequences were both
functional and a privacy problem:

- Anyone following the documentation got **no admin cookie injected**.
- That cookie value was **never added to the redaction patterns**, so it could
  reach reports and screenshots.

The variable is now `ADMIN_COOKIE` throughout. The old name is deliberately not
kept as a fallback — keeping it would preserve the identifier being removed.

## On editing release records

Two earlier release records named the third party directly, and one listed the
exact scenario filenames that had been deleted. Those records were
**de-identified, not rewritten**: every fact stays — what was removed, when, why
and what it cost — and only the third party's identifiers became placeholders.

The rule against editing a record after the fact exists to stop people hiding
their own mistakes. It does not require publishing someone else's product
details. Note the self-defeating case that prompted this: the v1.4.1 record
documented the removal of two private projects *by naming them*.

## Git history

The repository's history was reset to a single baseline commit
(`7bd6a67`, authored as `xcodethink@users.noreply.github.com`).

The path removals in 1.4.1 handled files that should not have existed. What
remained could not be fixed that way: 181,036 CJK characters across history —
160,459 of them in the 80 historical versions of `CHANGELOG.md` alone — plus
internal identifiers in 98 paths' historical versions, including `src/` source
comments. Rewriting file *contents* across every commit would have needed a
bespoke filter over 98 paths, where a single miss means doing it again.
Squashing is the only approach that is provably complete: there is exactly one
commit, and it contains exactly the tree that can be inspected.

**What was lost**: `git blame`, `git bisect`, 264 commits of history, and all
release tags for v0.3.0 … v1.4.1. npm remains the authoritative record of every
published version, and the GitHub releases keep their notes and SBOM artefacts.

**What was kept**: the file tree, byte for byte. Each rewrite asserted that the
resulting tree hash equalled the tree before it, and refused to push otherwise.

## Rollback plan

npm tarballs cannot be unpublished after 72h; rollback is fix-forward.

- **Code**: `git revert 7bd6a67` is meaningless against a single baseline commit.
  Roll forward with a patch instead.
- **npm (within 72h, emergencies only)**: `npm unpublish pixelcheck@1.4.2`, then
  `npm dist-tag add pixelcheck@1.4.1 latest`.
- **npm (after 72h)**: `npm deprecate pixelcheck@1.4.2 "use 1.4.3"` and ship a
  patch.
- **Do not roll back to reach the old behaviour.** 1.4.1 and earlier read the
  old environment variable name and carry the identifiers this release removed.

## Follow-ups

- **`ADMIN_COOKIE` is a silent behaviour change for anyone who had set the old
  variable.** It is called out in the changelog and the GitHub release. Nobody
  outside this project could plausibly have been using the old name, since it
  was never documented.
- **`NPM_TOKEN` expires ~2026-08-31.** Migrate to npm Trusted Publishing;
  `publish-mcp.yml` has now proved OIDC works end to end with no stored secret.
- **`darwin-x64` has no CI coverage** since `macos-13` left the matrix.
- **Consider `removeComments: true`** in `tsconfig.json`. Two of the leaks in
  this release reached the published package purely because source comments
  compile into `dist/`. A gate now catches the specific patterns, but not
  shipping comments at all would remove the category.
