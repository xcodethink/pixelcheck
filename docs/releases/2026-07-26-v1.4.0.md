## Summary

Everything in this release had been sitting on `main` since 1.3.0 without being
published — npm served 1.3.0 for eight weeks while the fixes were merged. This
release ships them.

**No breaking change to pixelcheck's own API.** The one compatibility-relevant
change is the bundled `sharp` moving to a new major (0.34 → 0.35) to clear HIGH
libvips advisories; it is a transitive upgrade for consumers.

Headlines:
- **Scroll-reveal false positives gone.** Full-page captures of
  IntersectionObserver + `opacity 0→1` pages rendered revealed sections as solid
  black, producing false high-severity "empty dark void" / "low-contrast body
  text" findings. `Recorder.settleAnimations()` now runs before every full-page
  capture. Viewport captures are untouched, so a genuinely stuck animation is
  still caught.
- **Tall pages score again.** A full-page screenshot over 8000px but under the
  2.5 MB byte-bypass was sent uncompressed and rejected by Anthropic
  (`overall_score: null`). `compressForVision` now enforces the 8000px edge
  limit first, and `compressForVisionMulti` reads tall pages as a macro
  thumbnail plus native-resolution slices.
- **No more false "perpetual loading".** A new phase-4 content-readiness gate
  waits for loading indicators to clear before capture — including a lone
  spinner, which the original cluster threshold (≥3) missed.
- **Dependency security.** `sharp` 0.35.3, `@hono/node-server` override
  `^2.0.9`, `hono` override `^4.12.21`, plus `form-data` / `protobufjs` /
  `fast-uri` / `body-parser`. `npm audit --production --audit-level=moderate`
  exits 0 (17 low remain, all one root cause: `@ai-sdk/provider-utils` via
  stagehand's optional/dev path, outside the production scope).
- **MCP registry metadata unstuck.** `server.json` had drifted to 1.2.1 —
  neither 1.2.1 nor 1.3.0 updated it — so `registry.modelcontextprotocol.io`
  still advertises 1.2.0. It is now 1.4.0 in the repo; the registry itself still
  needs a `mcp-publisher publish` (see Follow-ups).

## Rollback plan

npm tarballs **cannot be unpublished after 72h**; rollback is fix-forward, not
unpublish.

- **Code**: `git revert 9e64ad2` on a branch → PR → merge. `main` is protected
  (no force-push, includes admins) — never `reset --hard`.
- **npm (within 72h, emergencies only)**: `npm unpublish pixelcheck@1.4.0`, then
  re-point `latest`: `npm dist-tag add pixelcheck@1.3.0 latest`.
- **npm (after 72h)**: `npm deprecate pixelcheck@1.4.0 "use 1.4.1"` and ship a
  patched 1.4.1.
- **Re-point `latest` without unpublishing**: `npm dist-tag add pixelcheck@1.3.0 latest`.
- **Blast radius if the `sharp` major is the problem**: pin back with
  `"sharp": "0.34.5"` in a 1.4.1, and re-open the libvips advisories as known
  and disclosed in SECURITY.md.

## Follow-ups

- **MCP registry is two releases stale.** `registry.modelcontextprotocol.io`
  advertises 1.2.0 (published 2026-05-06); 1.2.1, 1.3.0 and now 1.4.0 were never
  pushed. `server.json` is correct at 1.4.0, but publishing needs the
  `mcp-publisher` CLI plus an interactive GitHub login for the
  `io.github.xcodethink` namespace. Worth automating in `release.yml` so it
  cannot drift again.
- **No CI check ties `server.json` to `package.json`.** That is exactly how the
  drift above went unnoticed for two releases. A three-line assertion in the
  public-API contract test would close it.
- **`macos-13` CI jobs never run.** Both matrix entries have sat in `queued`
  indefinitely on #60, #62 and #63 (GitHub no longer schedules Intel macOS
  runners for this repo), so every PR carries two permanently pending checks and
  `darwin-x64` gets no coverage — notable now that `sharp` ships distinct
  prebuilt binaries per platform. Either drop `macos-13` from the matrix or move
  it to a `continue-on-error` lane.
- **`NPM_TOKEN` expiry.** The granular automation token was issued 2026-06-02
  with a 90-day window (~2026-08-31). It worked for this publish; rotate before
  expiry, or migrate to npm **Trusted Publishing** (OIDC, no stored secret).
- **`@ai-sdk/provider-utils`** (17 low) clears when upstream stagehand updates
  its `@ai-sdk` dependencies. Out of production scope; no waiver needed.
