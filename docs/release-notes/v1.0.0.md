# PixelCheck v1.0.0 — Real Eyes and Hands on the Web for AI Agents

**Status**: Draft (final version stamped at `npm publish` time)

PixelCheck v1.0 ships an MCP server that gives AI agents the ability to actually see and operate the web. Local-first. Vendor-agnostic. MIT-licensed.

This is a **renaming + repositioning** release of what was previously published internally as `ai-browser-auditor`. No code regressions, no public users disrupted (v0.x was never on a public npm registry), and a backward-compat env-var alias keeps existing local installs working.

---

## What is PixelCheck

PixelCheck is an MCP ([Model Context Protocol](https://modelcontextprotocol.io)) server exposing **5 browser primitives** an AI agent can call to actually navigate, see, and operate real web pages:

```
see(url, opts)              snapshot a page (DOM + screenshot + console + network)
act(url, steps)             execute an action sequence (semantic + selector + Computer Use)
extract(url, schema)        pull structured data matching a Zod / JSON schema
judge(url, rubric)          score a page against a rubric ("is this dark-pattern free?")
compare(a, b, criteria)     A/B comparison of two URLs (incl. blind mode)
```

Each returns a strict JSON Schema response with cost / screenshot / DOM envelope. Composable. Cacheable. Auditable.

Drop into Claude Desktop, Cursor, Cline, Continue, Zed, or Claude Code via `~/.mcp.json` — your agent gets 17 tools (5 primitives + audit_url + explore_url + 10 meta) instantly.

```bash
npm install -g pixelcheck
pixelcheck doctor                # 8-check environment health
pixelcheck-mcp                   # start MCP server (stdio transport)
```

```jsonc
// ~/.mcp.json
{
  "mcpServers": {
    "pixelcheck": {
      "command": "pixelcheck-mcp",
      "env": { "ANTHROPIC_API_KEY": "sk-ant-..." }
    }
  }
}
```

## Highlights

### MCP-first architecture

- **17 MCP tools** — 5 primitives (`see` / `act` / `extract` / `judge` / `compare`) + 2 presets (`audit_url` / `explore_url`) + 10 meta (`list_personas` / `list_scenarios` / `list_capabilities` / `calibrate_critic` / `get_last_report` + …)
- **30 published JSON Schemas** with dual Ajv + Zod validation — strict contract for every tool result
- **67 named public API exports** snapshotted via SemVer-locked surface (breaking changes only at major versions; see [Stability Commitment](../../README.md#stability-commitment))
- **MCP self-describe** — `list_capabilities` lets agents discover all server features programmatically (Result Schema version, env var defaults, primitive list, persona/scenario counts)

### 18-persona / 15-country audit preset

PixelCheck still bundles the original v0.x audit preset on top of the primitives — a CLI-first composition that runs "real users review your product" after every deployment. 18 personas across 15 countries / 5 script systems (Latin / CJK / Arabic / Cyrillic / Devanagari) with full mental-model + critical-concerns descriptors.

### Reliability

- **5-layer reliability stack** lifting Stagehand baseline ~75% to 98-99% step success: Stability Gate → LLM Rewrite → Selector Hint → Auto Selector Discovery → Computer Use
- **9 anti-detection fingerprints + 15 stealth patches** so audits look like real users, not bot-flagged sessions
- **Cross-session memory + plan cache** (60-80% hit rate on repeat audits, 30-day TTL)
- **Cost guard** — per-run + per-day USD caps + cross-process advisory lockfile prevents double-spending
- **3 cost-tier modes** — `economy` (Haiku only), `balanced` (Haiku primary + Sonnet escalation, 3-5x cheaper), `max` (always Sonnet)

## BREAKING CHANGES — read MIGRATION.md

This release renames the package and CLI. **Everything else is behavior-compatible** with v0.3 (no result-schema breakage, no config-file breakage, no scenario-YAML breakage).

| Concept | v0.3.x | v1.0.0 |
|---|---|---|
| npm package name | `ai-browser-auditor` | `pixelcheck` |
| CLI bin | `ai-audit` | `pixelcheck` |
| MCP server bin | `ai-audit-mcp` | `pixelcheck-mcp` |
| Default data home | `~/.ai-browser-auditor/` | `~/.pixelcheck/` |
| GitHub repo | `xcodethink/ai-browser-auditor` | `xcodethink/pixelcheck` (auto-redirect) |
| Brand H1 | "AI Browser Auditor" | "PixelCheck" |
| Tagline | "Your AI-powered product experience reviewer" | "MCP server giving AI agents real eyes and hands on the web" |

**Backward compatibility shipped**:
- `AUDIT_HOME` env var still respected (so v0.x users with explicit `AUDIT_HOME` settings keep working)
- `pixelcheck` reads both new `PIXELCHECK_HOME` and legacy `AUDIT_HOME` env vars; new wins if both set
- GitHub auto-redirects the old `ai-browser-auditor` repo URL

**Not shipped, but available next minor**: deprecation warnings, automatic data migration on first run.

See **[MIGRATION.md](../MIGRATION.md)** for full v0.3.x → v1.0.0 migration steps and the command-by-command mapping table.

Decision rationale in **[ADR-033](../decisions/ADR-033-rename-to-pixelcheck.md)**.

## Why local-first + vendor-agnostic

Two design choices behind PixelCheck:

**Local-first.** Runs entirely on your machine. The only outbound network destination is the LLM provider you point your agent at. No telemetry. No remote storage. No SaaS sign-up. Screenshots, DOMs, business flows stay on your laptop. See [PRIVACY.md](../../PRIVACY.md) for the full data-flow disclosure.

**Vendor-agnostic.** PixelCheck doesn't lock you into a model provider. The MCP server is provider-neutral — your agent decides which LLM to use. Multi-provider abstraction (OpenAI, Gemini, Ollama as primary) is on the v1.x Wave 2 roadmap. The reason is simple: AI agents in 2026 are best-of-breed multi-model systems, and tools that lock you to one provider die.

This is the inverse of where most "AI browser" SaaS is going. PixelCheck is a single npm package you install, run, and own. MIT-licensed. No telemetry. No lock-in.

## Try it

```bash
# Global install (recommended for standalone CLI / MCP server use)
npm install -g pixelcheck
pixelcheck doctor
pixelcheck-mcp

# Or per-project
npm install pixelcheck --save-dev
npx pixelcheck init projects/my-app --name "My App" --url "https://myapp.com"
npx pixelcheck run --project projects/my-app
```

For the audit preset (the original v0.x scope, now a primitive composition):

```bash
pixelcheck init projects/my-app --name "My App" --url "https://myapp.com"
pixelcheck run --project projects/my-app
```

Output: `audit.json` + `audit.html` (dark-theme dashboard) + `audit.pdf` (stakeholder report) + `audit.sarif` (GitHub Code Scanning) + per-step screenshots + video + HAR + console log.

For CI integration, exit codes `0`/`1`/`2` map to pass/fail/warn.
